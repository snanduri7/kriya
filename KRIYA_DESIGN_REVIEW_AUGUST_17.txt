Remove the candidate workspace.

- Python signature mode drops `def` lines.
- Java signature mode includes imports/type declarations but omits constructors/methods.
- This explains wrong-file repair in the Ignite/Qpid protocol incident: constructor/encode/decode/equals logic was invisible, so triage guessed configuration files.

Required:

- Parse assertions, stack frames, verification markers and chained exceptions.
- Rank root-cause frames above wrapper frames.
- Include implicated method bodies, callers, constructors, equality/serialization logic and relevant configuration.
- Use LSP/tree-sitter spans and scoped call/data-flow relationships.
- Return ranked multi-file candidates.
- Low confidence expands context; it must not force one guessed target.
- Apply negative evidence: if broker startup/send/receive succeeded, deprioritize broker configuration.
- Build incident tests and measure attribution top-1/top-3 recall.
- Cover multi-file fixes and chained-exception depth.

### P1-6: Introduce an explicit failure/retry state machine

Required:

- Enum-backed failure types.
- Immutable `PrimaryFailure`.
- Separate `AuxiliaryDiagnostic`; optional subsystem errors can never replace the primary failure.
- Signature includes gate, normalized output fingerprint, locations and candidate hash.
- Retry budgets per failure signature.
- Transitions:
  - same candidate + same failure: never repeat
  - new candidate + same failure: bounded retries
  - new failure after repair: progress; new local budget
  - repeated parser/anchor failure: change edit strategy
  - low-confidence attribution: widen evidence
- Final Reviewer failure must not fail an already-correct/applied result.
- Audit lookup, LSP, MCP, skill extraction and reviewer paths for auxiliary-error overwrite.

### P1-7: Replace fuzzy response policing with typed edit operations

Normalize all model output into one internal `CandidateEdit` with exactly one operation:

- `create_full_file`
- `repair_with_patch`
- `repair_with_full_file`
- `no_change_assessment`

Use one response per file and a small marker/state-machine protocol; do not require large source files to be JSON-escaped.

Operation invariants:

- Patch: nonempty uniquely matching search block and changed replacement.
- Full repair/create: complete content.
- No-change: reason required; allowed only in repair/broadcast contexts.
- Path and base content/hash come from Kriya, not model claims.

Separate checks:

- Hard deterministic rejection: no-op, stale/missing anchor, invalid path, structural corruption, malformed protocol.
- Replay original validator when cheap: static rule, syntax, compile, POM, targeted test.
- Runtime verification remains downstream authority when expensive.
- Fuzzy diagnosis-to-diff matching becomes telemetry or at most one bounded veto.

The current per-file bounded veto and compile/POM/targeted-test bypass are acceptable transitional protections. Stop adding new substring exceptions to `find_edits_ignoring_own_diagnosis()`.

### P1-8: Make validation coverage explicit

Return `passed`, `failed`, `skipped` or `unavailable`; never represent unsupported validation as `success: true`.

Required:

- Autonomous apply cannot treat skipped/unavailable as passed.
- Add JS/TS, Go, Rust and .NET adapters, or explicitly limit advertised support.
- Derive commands from manifests/scripts before asking an LLM.
- Use incremental `mvn compile` during retries; reserve clean builds for final verification or suspected stale state.
- Pytest exit code 5 becomes `no_tests_collected`, not unconditional pass when tests were expected.
- Package installation/network follows egress policy.
- Full regression runs before apply.
- Generated `[VERIFICATION] PASS` is evidence, not an independent production oracle.

### P1-9: Build a role-aware prompt compiler

Required:

- Hard budgets for system, task, failure, repository, skills, sibling files and output.
- Actual tokenizer or calibrated per-model estimator.
- Deduplicate repeated rules.
- Retrieve only relevant skill rules/examples.
- Treat repository text, errors, logs and web content as untrusted data, never instructions.
- Planner receives summary/constraints.
- Architect receives interfaces/file responsibilities.
- Developer receives exact relevant slices.
- Reviewer receives diff plus gate evidence.
- Use stable prefixes for local prompt caching.
- Skip Planner/Architect for small, deterministic repairs.

Planner-code reuse is correlated with incidents but not proven causal. Keep it behind an experiment flag and decide through A/B metrics rather than assumptions.
