The issue is in the C# call site processing logic in `graphify/extractors/engine.py`. When processing generic method calls like `Get<int>("port")` or `this.Get<int>("port")`, the code extracts the full text including type arguments (`"Get<int>"`) instead of just the bare method name (`"Get"`). This causes callee lookups to fail because the index is keyed on the bare name.

The fix needs to extract the bare method name from `generic_name` nodes in two places:
1. When processing `member_access_expression` nodes where the name field is a `generic_name`
2. When processing direct `generic_name` function calls

Looking at the existing code, I can see that `_csharp_collect_type_refs` already handles `generic_name` nodes properly by extracting the identifier part, so we can reuse similar logic.

First, I'll identify and fix the issue in the member access expression handling (lines ~5356-5370) where `callee_name = _read_text(mname, source)` is used directly on a generic_name node. Then I'll also check for direct generic calls.
