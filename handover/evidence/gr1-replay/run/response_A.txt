Analysis:
The issue is in the C# call site extraction logic in `graphify/extractors/engine.py`. When processing generic method calls like `Get<int>("port")` or `this.Get<int>("port")`, the code incorrectly extracts the full name including type arguments (`"Get<int>"`) instead of just the bare method name (`"Get"`). This causes callee lookups to fail because methods are indexed by their bare names. The fix needs to extract the base method name from `generic_name` nodes when they appear in call sites.

Looking at the current code, I can see that:
1. For member access expressions with generic names, it calls `_read_text(mname, source)` which returns the full generic name including type arguments
2. There's already logic elsewhere in the same file that properly handles `generic_name` nodes by descending into them to read `type_argument_list`
3. The fix should extract just the method name part from `generic_name` nodes

I need to modify the code to detect when `mname` is a `generic_name` and extract only its identifier part, similar to how other parts of the codebase already handle this pattern.
