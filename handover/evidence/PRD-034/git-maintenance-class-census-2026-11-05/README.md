# CERT-GIT-MAINTENANCE-CLASS-001 - mechanical closure of the git auto-maintenance snapshot race (2026-11-05)

Owner correction: "close the entire defect class mechanically before another hosted run". Nothing here is a hand-maintained candidate list.

## Mechanism (MEASURED on hosted runs 41785193323, 41812207261, 41840628981; reproduced on Linux git 2.56.0)
Every command that runs `run_auto_maintenance` (commit, merge, fetch, pull, am, rebase, receive-pack) starts `git maintenance run --auto --quiet --detach`. For a moment that child holds `.git/objects/maintenance.lock` and moves the mtime of `.git/objects`. A test that snapshots a repository (lists `.git` / `.git/objects`, hashes it, copies it) after an unguarded fixture commit sees a difference no Kriya write caused. `gc.auto=0` alone does NOT stop it; the guard is `-c maintenance.auto=false -c gc.auto=0`. Mac git 2.54.0 did not show the race in 0/2,100 trials; Linux git 2.56.0 did (51/1,500) - the tripwire therefore observes BEHAVIOUR (commit + listing), not the outcome, so it works on any host.

## 3. The permanent tripwire (tests/_git_quiescence.py + the autouse fixture in tests/conftest.py)
* CPython audit hook installed once; no `os.stat` wrapper (`shutil` compares `os.stat` by identity).
* Population: every `subprocess.Popen` of a commit-class git (keyed by the repository's real path, helper = innermost non-library frame, product flag = any `kriya/` frame) and every `os.scandir`/`os.listdir` of `<repo>/.git` or `<repo>/.git/objects`. A test that listed a repository with an unguarded commit FAILS at teardown, naming the helper and the observer. `KRIYA_GIT_QUIESCENCE=report:FILE` is the census mode.
* Guard recognition: argv `-c maintenance.auto=false`, `GIT_CONFIG_PARAMETERS`, or `GIT_CONFIG_COUNT/KEY/VALUE` (no global env workaround: Kriya has its own GIT_CONFIG_* contract).
* Fixes made on the way: observer attribution named `<frozen os>:walk` (abspath before the library test) -> now names the helper; pylint false positive removed.
* Launch routes covered (each with a synthetic unguarded control AND a guarded control): `subprocess` git argv, `shell=True` string, `sh -c` / `bash -c` text (with `cd DIR &&` and `git -C DIR`, a per-segment guard so a guarded first command never excuses an unguarded second one), `os.system`, `os.posix_spawn`/`os.exec*`. A text-form scan of every test source found NO executable unguarded shell-text commit-class git (8 hits, all comments/prose).
* Proven by tests/test_git_quiescence_tripwire.py (70): rules; a synthetic NEW unguarded helper is caught and the same helper guarded is not; a pruning walk is not an observer; trace2 agrees with the inference both ways; **mutation of 15 real helpers** (`named_test_oracle_harness.make_base`, `b2c_fixtures.maven_workspace`, `kup_workspace._repo`, `s19e._repository`, `logging_location._git_workspace` + the 10 census-guarded ones: stripping the guard makes the tripwire fire for every one); an end-to-end run of the REAL conftest fixture in a subprocess pytest (only the unguarded snapshotting test errors); report mode; judge(); shell-script ratchet (per FILE and per unguarded LINE count: a second unguarded line in a listed script fails) with 9 negative controls; bare-stat scan with 5 controls; external-copier scan (`tar`/`rsync`/`ditto`/`cp -R`/`diff -r`, argv and command-string forms) with 6 controls; 6 launch routes x guarded/unguarded.
