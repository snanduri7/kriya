The issue is in the C# call site processing logic in `graphify/extractors/engine.py`. When a call has a generic name (like `Get<int>`), the current code uses `_read_text(mname, source)` which returns the full text including type arguments. This causes lookup failures because method indices are keyed by bare names.

The fix needs to extract just the method name from `generic_name` nodes when they appear in member access expressions or as standalone function calls. The code already handles generic names properly for `references[generic_arg]` edges, so we just need to adjust how we compute `callee_name`.

Looking at the existing code structure, I need to modify two places:
1. When processing member access expressions with generic names
2. When processing direct identifiers that are generic names

The solution is to detect when a node is a `generic_name` and extract its identifier part (before the `<`) instead of using the full text.
