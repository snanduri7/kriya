# Egress (PRD-012), inference runtime port (INF-001), provider contract, model identity/qualification/budgets (PRD-013..016), fallbacks/metrics/routing (PRD-017..019)

_Moved verbatim from CLAUDE.md on 2026-10-07 (loaded on demand, not every session). Read before modifying any module named here. Code is ground truth; update this file when behaviour changes._

### Egress control (`kriya/core/llm.py`, `kriya/memory/vector.py`, `kriya/policy/egress.py`) — PRD-012
`LLMClient.complete` enforces `autonomy.egress_policy == "local_only"` by resolving the target base URL's hostname and rejecting anything not loopback/private/`.local` (`is_local_url`), raising `EgressViolationError`. `OllamaEmbeddingClient` (`kriya/memory/embedding.py`) enforces the same boundary before any request (`egress_policy` is a REQUIRED constructor keyword; a refusal is never retried). This is a safety boundary, not a convenience check — don't bypass it silently when adding new LLM/embedding call sites.


`autonomy.egress_policy` is a closed vocabulary, exactly `local_only` (default) or `unrestricted`, validated like `shell_network`/`contract_change_escalation` (case-sensitive; a typo is a config error, never the permissive branch — every consumer compares against `"local_only"`). The production profile seals it to `local_only`.
PRD-012 normalizes every channel's network authority into one vocabulary, `kriya/policy/egress.py::EgressCapability` (`denied`/`registry_only`/`approved_public_knowledge`/`explicit_destinations`/`unrestricted`) via `capability_for()`, keyed on each owner enum's `.value` (NetworkAuthority/MCPNetworkAuthority are deliberately NOT extended - `OCIContainmentBackend.prepare()` has no exhaustive-match guard). It records, never decides: `kriya/workflow/egress_authority.py::describe_run_egress(cfg)` is persisted once per run as the `egress.authority` run event, and every contained process carries `ProcessResult.egress` (-> gate outcomes via `validate.execution_evidence()`, and ShellTool's result). `autonomy.shell_network` (`unrestricted` default = SEC-005's documented privileged behaviour; `denied` = non-package-manager shell commands get no network, recognized package managers stay registry-scoped; SECURITY_AUTHORITY) - the production profile seals `denied` and `knowledge.offline_mode: true` (KnowledgeGuard never sends goal-named library names to public registries). With containment required ShellTool is always contained even when `sandbox_execution` is off. `tests/test_prd012_network_inventory.py` inventories every outbound client in `kriya/`+`plugins/` with its governing authority - a new `httpx`/`AsyncOpenAI`/`urlopen`/... site fails it until classified.

### Inference runtime port (`kriya/core/inference_runtime.py`) — INF-001
`workflow / agents -> LLMClient (the inference service) -> InferenceRuntimePort -> runtime adapter`. Kriya keeps routing, qualification, fallback, retries (the reasoning `response_format` retry, the empty-content floor retry), budgets, egress/authority, evidence, metrics, tool-argument validation and run state in `LLMClient` and above; an adapter owns only the transport (`complete`/`complete_with_tools` -> `ChatResponse`/`RawToolCall`), per-request context-window translation (`configured_/with_/without_context_window`, `capabilities.per_request_context_window`), the identity `probe`, `classify_error` (`RuntimeErrorKind`; only REQUEST earns a changed-request retry) and `list_models`. The packaged default `OllamaRuntimeAdapter` is registered in `kriya/core/model_runtime.py` (still the only module naming a provider) on the shared `OpenAICompatibleTransport` (the only `chat.completions.create` caller). A binding selects one with `inference_runtime` (None = default; SECURITY_AUTHORITY, also inside `agent_llms` roles); an unregistered name (vllm included) raises `UnknownRuntimeAdapterError`, never falls back. A runtime without a per-request window gets none sent; the budget uses the probe's served window, else labels the declared one `provider_managed`. Keep the patch points: `LLMClient._request_once`, `llm.client.chat.completions.create`, `model_runtime.probe_model_runtime`/`_http_json`, `LLMClient._dispatch_budget`. `tests/test_inf001_runtime_parity.py` pins the wire and the runtime digest (never bump `MODEL_PROTOCOL_ADAPTER_VERSION` or add the adapter name to `identity_fields` without re-qualification); `tests/_fake_inference_runtime.py` is test-only (kriya/ must never register it); `tests/test_inf001_runtime_port.py` is the contract + layering suite (`kriya/workflow`/`kriya/agents` name no adapter, transport or SDK). Fingerprints are cached per (adapter, endpoint, model, window, protocol); qualification records are parsed once per process while unchanged (mtime/size revalidated). The future `VllmRuntimeAdapter` extension point is documented in the module docstring and `handover/INF_001_RUNTIME_PORT.md` (not implemented).

### Provider contract (`kriya/core/provider_contract.py`, `kriya/core/model_runtime.py`) — PROVIDER-CONTRACT-001
Invariant: a setting Kriya records, budgets against, qualifies or treats as authoritative is proven to reach the provider with the intended semantics, or Kriya fails closed. Desired configuration is not effective identity. Measured facts (Ollama 0.34.4): `/v1` ignores every `options.*` field and top-level `top_k`; it applies top-level temperature/top_p/seed/`reasoning_effort` (any string gets HTTP 200, so Kriya refuses values outside `REASONING_EFFORTS`); the served window is the model's `num_ctx` PARAMETER, else the server env (`OLLAMA_CONTEXT_LENGTH`); an over-long prompt is silently truncated.
- **Plan.** An adapter turns a binding's `extra_body` (the provider's dialect) into a `ProviderRequestPlan`: the exact wire body plus each semantic setting's requested/effective value, `Support` (SUPPORTED / SERVER_CONFIG_ONLY / OBSERVABLE_ONLY / UNSUPPORTED) and `Provenance`. SERVER_CONFIG_ONLY settings are compared with the served model's PARAMETERs (`fingerprint.server_parameters`). `plan.enforce`: conflicts always refused; unknown fields and not-effective settings refused under `runtime_profile: production`, recorded otherwise. `reasoning: false` is sent as `reasoning_effort: "none"`.
- **Context.** Requested, served (observed via `/api/ps`, else server model config) and budget windows are separate (`context_window_state`); served < requested is always `SERVED_CONTEXT_BELOW_REQUESTED`; served != requested under production is `RUNTIME_CONTEXT_IDENTITY_MISMATCH`; every sizing site uses `budget_window` (never a larger served window). `/v1` takes no per-request window, so no PRD-016 tiers there. Pin a window/top_k with `kriya model pin` (a content-named derived model carrying only the binding's server-only values) and bind the pinned tag.
- **Transport.** One AsyncOpenAI per (endpoint, key) in `LLMClient._client_for`: SDK `max_retries=0`, Kriya timeouts (`llm.transport`, SECURITY_AUTHORITY) sent per request and capped by the deadline (below), `trust_env=False` (no inherited proxy), `aclose()` (the CLI closes every client via `_closing`). A stream is one request, never resent. Any per-request timeout must come from `llm.transport` - a timeout set on the SDK client is overridden (`qualification_client_factory`).
- **After the call.** On an exact runtime, a response whose reported prompt tokens are below `consumption_bytes / bytes_per_token_ceiling` (whitespace runs counted once; ceiling from qualification, never below `DEFAULT_BYTES_PER_TOKEN_CEILING`) is `PROVIDER_PROMPT_TRUNCATED`; served-window violations too; both become `CompletionStatus.PROVIDER_CONTRACT_VIOLATION`, a deterministic `provider_contract` stop. Each call records a `provider_contract` protocol entry (settings identity, context state, timeouts, consumption verdict; no prompt text).
- **Deadline (PROVIDER-CONTRACT-001A F-1).**
  - **One clock per run.** A mutating run has ONE generation clock (`run_coordinator.claim_run_generation_clock`), started by the run's first model call or generation pass. No work unit, retry or role restarts it.
  - **Admission.** Admission reads it (`GenerationState.budget_started_monotonic`). `generation_started_monotonic` stays the invocation's own wall-time clock.
  - **Each call.** A call's deadline is clock + `autonomy.generation_time_budget_seconds`, narrowed (never extended) by an `inference_deadline()` cap. The request is bounded in total (`_within_deadline`, so a stream cannot outlive it).
  - **Typed stop.** `InferenceDeadlineError` (`INFERENCE_DEADLINE_EXHAUSTED` before any provider contact, `_EXCEEDED` mid-request) is never escalated or resent. In an attempt it is the `time_budget_exhausted` stop; at the final review it is a typed refusal.
  - **Telemetry.** `provider_contract.deadline`; no budget means `deadline_bound=false`.
- **Served-context observation (F-3).**
  - **Typed outcome.** `observe_served_context_state` returns one of observed / not_loaded / loaded_without_window / observation_failed / not_applicable. One bounded retry; nothing is cached (never re-add a negative cache).
  - **Production.** Strict production on an exact runtime that declares observation refuses a result whose window was not observed after the call (`SERVED_CONTEXT_UNOBSERVABLE`). Unloaded before the call is fine.
  - **Elsewhere.** Outside production it is recorded as unverified.
  - **Tests.** Test stand-ins of an exact production runtime must report the served window (`test_prd017_fallback_transition._exact_ollama`).
- **Over-context (F-2).**
  - **Production adapter.** Production uses `inference_runtime: ollama_native` (`/api/chat`, `truncate:false`, adapter `kriya-ollama-native/2`). An over-window prompt is refused by the provider as `PROVIDER_PROMPT_TRUNCATED`, with the exact `provider_prompt_tokens`.
  - **Why not `/v1`.** `/v1` answers it from a truncated prompt (measured: window/2+2 tokens) and cannot pass qualification `/8`'s `over_context_refusal`, which every role requires.
  - **Admission misses.** Admission said it fits, the provider refused: recorded as `provider_contract.admission_miss` (content-free).
  - **The byte check below** is defence in depth only.
- **Unproven settings.** A setting whose effect is not established is UNSUPPORTED (e.g. `presence_penalty`, measured: no effect on either adapter). It is never sent, and its effective value is unverified; a served model's configured value is kept as `SettingState.server_config_observed`, never as the effective value. Strict production refuses any *requested* UNSUPPORTED setting (`PROVIDER_SETTING_UNSUPPORTED`). The port's default plan carries a setting only as the adapter's `provider_capabilities` declare it.
- **Budgets.** Each role has its own output budget (`agent_llms.<role>.max_output_tokens`); a reasoning identity adds its qualified `reasoning_tokens_max` (`llm.reasoning_max_tokens`), else the 12288 floor.
- **Doctor.** `model.provider_contract` (required): a controlled probe of each role model; PASS only when every relied-on setting is carried or verified and the served window equals the requested one.
- **Tests.** `tests/test_provider_contract_001.py` (wire, retry count, proxy, timeout, context, truncation, pin, doctor, budgets, qualification identity); `tests/test_provider_contract_001a.py` (run deadline, observation, `/8` refusal case); `tests/test_provider_contract_native.py` (native wire and parity). Test fakes on an exact runtime must report realistic prompt usage (`tests/_provider_usage.py`); a runtime taking a per-request window is `tests/_per_request_window_runtime.py`.

### Model runtime identity, qualification, results and budgets (`kriya/core/model_runtime.py`, `model_qualification.py`, `completion.py`, `token_budget.py`) — PRD-013..016
**Identity (PRD-013):** `ModelRuntimeFingerprint` is built only from what the configured endpoint reports (Ollama `/api/version`, `/api/tags` digest, `/api/show` verbose: weights blob, quantization, RENDERER/PARSER, tokenizer vocab digest, normalized parameters, served capabilities) plus Kriya-side inputs (resolved capability profile, sent `num_ctx`, `MODEL_PROTOCOL_ADAPTER_VERSION` - bump it when request/response handling changes). Missing components are `"unavailable"`, never inferred from the name; timestamps never enter the digest; `exact` = artifact digest + provider version known. Probed once per process per runtime input (every result cached; doctor/qualify/status re-probe), never for a non-local endpoint under any egress policy. `tests/conftest.py` sets `KRIYA_MODEL_RUNTIME_PROBE=0` (and a temp `KRIYA_QUALIFICATION_HOME`) for every non-`live_model` test so a mocked test can never reach a developer's real Ollama - probe tests inject a transport. Every `LLMClient` call records its fingerprint (`last_call_metrics`, `RunRecord.model_runtime_fingerprint_ids` via `run_coordinator.record_model_runtime_use`, `<state>/model_runtimes/<digest>.json`); the resume `model_runtime` fingerprint binds every role model's exact runtime.
**Qualification (PRD-014):** `kriya model qualify|status|fingerprint`. Records keyed by the qualification identity = fingerprint digest + inference-settings digest (MODEL-QUAL-IDENTITY-001, `kriya/core/inference_settings.py`: settings /3 since PROVIDER-CONTRACT-001: temperature, reasoning flag, the adapter's WIRE body (what the provider receives - on Ollama /v1 top-level top_p/seed/reasoning_effort, never `options.*`) plus the server-only settings the binding requests (top_k, ...; `server_config`); max_tokens is metadata only), checked with adapter version + `QUALIFICATION_POLICY_VERSION` (now /8, PROVIDER-CONTRACT-001A: every role requires `over_context_refusal`; /4: a record binds the EFFECTIVE identity - `require_verified_identity` refuses with `QUALIFICATION_IDENTITY_UNVERIFIED` before any case when a setting is conflicting, unknown, not applied or unverifiable, e.g. an unpinned served window; every /3 record is STALE; a /2 record is found by runtime digest and reported STALE, never MISSING), stored OUTSIDE the workspace (`~/.kriya/qualifications`), stale on any drift. Every consumer passes the role's settings (`role_inference_settings`/`binding_inference_settings`); a call to any model executes with that model's OWN binding settings (`LLMClient._binding`: temperature + extra_body; a fallback never inherits the primary's sampling), the Reviewer on the primary sends `reviewer_temperature` - qualified inference identity == executed inference identity, and every `CompletionResult` carries `inference_settings_digest`; LLMClient dispatch uses the request's actual settings (`request_settings`). A differing `llm.retry_temperature` is a second Developer identity (`retry_inference_settings`/`role_inference_identities`): qualify, status, doctor, resume and Developer routing enumerate it, the PRD-017 profile carries `retry_qualification`, and under `runtime_profile: production` a Developer retry carrying it is refused before any request unless that exact identity is QUALIFIED (`attempt._require_qualified_retry_identity`, terminal `RETRY_INFERENCE_IDENTITY_NOT_QUALIFIED`, failure_category `retry_identity_not_qualified`); outside production it is recorded, not refused. `qualify` qualifies each distinct role identity of the model. A declared tier is offered only while the tier runtime has no record under any settings or policy. **Qualification policy (QUAL-CONFIG-001):** case budgets, capacity-probe bounds, cancellation timing and measurement margins come from `model_qualification` (`ModelQualificationConfig`, SECURITY_AUTHORITY as a whole; defaults = the /3 literals). Never add a policy literal to a case: use `_case_budget`/`_policy(ctx)`. Literals that are the test itself stay, with a comment. `reasoning_max_tokens` applies when the qualified identity sends `reasoning: true`, never by model name. Records store `qualification_policy` + `qualification_policy_digest`, and one under another policy is STALE. A pre-change record stands for `LEGACY_V3_POLICY_DIGEST` (pinned against an explicit literal table in `tests/test_qual_config_001.py`). Every production `assess` passes `policy_digest=policy_digest_for(cfg)` (structural test). **Environment identity:** capacity evidence (`ENVIRONMENT_DEPENDENT_CAPABILITIES` = `context_capacity`) is stored per execution-environment digest in `environment_evidence` and counts only in that exact, observable environment (`kriya/core/execution_environment.py`: OS/arch, runtime/version, accelerator backend/model/count, memory classes, runtime parallelism; never hostnames, serials, free memory or temperatures; observable only for loopback endpoints); functional cases hold in any environment; `save_record` keeps other environments' evidence. **Portability (INF-001 seam):** only `kriya/core/model_runtime.py` knows a provider's name or its per-request context field (`with_context_window`/`without_context_window`/`configured_context_window`/`supports_per_request_context_window`); a tripwire test fails on `provider ==`/`"num_ctx"` anywhere else in `kriya/`. **Requested window (FALLBACK-CONTEXT-WINDOW-001):** a binding's window has ONE definition, `requested_context_window(extra_body, context_window)` (an explicit provider option wins, deterministically, else the declared `context_window`), and `request_extra_body` puts it into every LLMClient request (primary and fallbacks, override bodies included) - so budget (`_dispatch_budget`), allocation (`allocation_window`), routing (`_served_window`), transition profiles, qualification (`qualification_config`), doctor and the runtime fingerprint (`resolve_configured_model_runtime`, which looks up the model's declared window; the embedding model has none) all agree with what is sent. Only the seam and LLMClient (reading back the request body) call `configured_context_window` (tripwire in `tests/test_fallback_context_window_001.py`). `effective_context_window` comes only from the served model's own `num_ctx` PARAMETER (never seeded from the request); budget `window_source`: `served_observed` (/api/ps), `server_model_config`, `requested_per_request`, `requested_unverified`, `provider_managed`; served < requested is refused (`SERVED_CONTEXT_BELOW_REQUESTED`), never budgeted down. A declared window an explicit option overrides is logged at LLMClient start and listed in doctor's `model.runtime_fingerprint` evidence (`context_window_overrides`). The same weights under another provider/version are a different runtime digest, so they never share evidence. The runtime fingerprint itself is unchanged (role independence/metrics/routing keys unaffected); the resume `model_runtime` fingerprint also binds every role's settings digest. `required_capabilities(cfg, role, model)` = base cases + role cases + every protocol the capability profile enables; `doctor --production` FAILs `model.qualification` unless every model of every role (binding + chain) is QUALIFIED. UNAVAILABLE is never PASS; qualification never executes model output on the host. Offline fixture conformance (`model_capabilities`) stays separate.
**Normalized result (PRD-015):** `LLMClient.complete_result()`/`complete_with_tools_result()` return `CompletionResult` (status OK/EMPTY_CONTENT/MALFORMED_STRUCTURED_OUTPUT/OUTPUT_TRUNCATED/BACKEND_ERROR/TIMEOUT/CANCELLED, reasoning presence but never its text, normalized native/Hermes/Qwen-XML tool calls). `complete()`/`complete_with_tools()` are compatibility wrappers (same return values, same raised exceptions); `llm.last_completion` holds the normalized result. Leading `<think>` blocks are always hidden; blocks elsewhere only for reasoning models (generated source may contain the tag text). The Developer rejects a truncated answer (`OUTPUT_TRUNCATED` protocol error) on the full-file and batch paths - add new capability-sensitive callers on the normalized API.
**Allocation + dispatch budget (PRD-016, CTX-001):** prompt builders size sections against `context_budget.allocation_window(cfg, binding)` (budget window = requested, never a larger served one (`provider_contract.budget_window`) - the request's own output reserve (role output + measured reasoning, capped at half) - framing - 256 safety margin, converted with the dispatch counter's ratio), never the raw `context_window`: graph pool 0.60 (design/plan reserved first), retry evidence 0.15, siblings 0.15, investigation evidence <=0.10; **PROMPT-BUDGET-FIT-001A/B:** a request whose fixed text is known sizes its variable sections from `request_capacity(cfg, binding, role=, output_tokens=)` (budget window - that request's own preferred output (the role's output, plus for a reasoning identity its QUALIFIED `reasoning_tokens_max` via `llm.reasoning_max_tokens`, the fixed 12288 floor only when unmeasured) - framing - safety margin, counted with the dispatch counter) minus its mandatory fixed text, via the one primitive `fit_variable_section` (built at the room, re-measured, rebuilt smaller at most 3 times, else left out - never forced in; the fixed text is never trimmed, so a genuinely oversized request is still refused, and the final review keeps 001C's `final_review_refused`): the direct Planner (`fit_planner_request`: graph context, then the fenced reference - repository evidence outranks untrusted text; the graph pool above stays its upper bound), the enforce structured Planner (PLANNER-CONTEXT-FIT-001: its structural relationships by priority - lines of grounded owners and Code Intelligence candidates kept first, whole lines plus an elision count - then the reference into what is left, refitted on every request, repair rounds included; goal, protocol, requirements, owners and the candidate map are never trimmed) and every Reviewer request (`review_requests`: pre-approval, final, `kriya review`; its own binding and output; no room -> one request with `REVIEW_FILES_OMITTED_NOTE`). **PROMPT-FIT-ROLE-CHAIN-001:** Planner/Reviewer requests are fitted per role candidate (`CandidatePrompts` -> `BaseAgent.run(candidate_prompt=)`; capacity from `candidate_request_capacity`, output from `agent.candidate_output_tokens`, the rule `call_with_escalation` itself uses - never size a fallback's request from the first model). **DEVELOPER-PROMPT-FIT-001:** every Developer request is fitted by `fit_developer_request` into the capacity of the binding it goes to (`DeveloperRequestFit` from `_run_developer_generation`; branches register their graph/reference as `OptionalSection`s via `_developer_optional_sections`, investigation evidence registers itself); order kept: planned_source, siblings, graph, investigation, learned reference; everything else is mandatory, never trimmed. **GRAPHIFY-OVERSIZE-REQUEST-001:** a bounded enforce subtask's planned files never reach the Developer as verbatim text: `WorkflowController` passes their paths (`split_planned_source` -> `run_generation_workflow(planned_source_files=)`) and the attempt renders them through `build_code_context` tiers as the optional `planned_source` section (`_planned_source_context`, same exclusion set as graph context, so an attempt-1 known target is rendered only by its budgeted known-target package). Never fold file content into `supplementary_context`: it becomes mandatory `skills_prompt` text no request fit can shrink. **Prompt-fit closure (Wave 7):** the Architect request is fitted per role candidate exactly like the Planner's (`fit_planner_request(..., request="architect")` via `CandidatePrompts`); the investigation loop fits its first request with the Developer's own `DeveloperRequestFit` (tool schemas counted as fixed cost) and both it and the self-correction loop stop (`REQUEST_FULL` / incident `request_full`) before a turn whose conversation (`context_budget.conversation_tokens`) no longer fits - never a request the dispatch check must refuse. Reductions are `context.request_fit` run events (enforce: a DecisionLedger record; Developer: `model.optional_context_reduced` reason `request_fit`); `build_code_context`'s budget is a bound (files that do not fit even as signatures are left out as `budget_exhausted` and named). `token_budget.plan_dispatch` runs inside `complete_result`/`complete_with_tools_result` before every request: counts the full dispatch (exact registered counter > qualified ASCII/non-ASCII ratios > default 2.5/1.5 bytes per token), treats the served window and `max_tokens` as PREFERRED values and, under `llm.context_policy.mode: adaptive`, selects the smallest offered larger tier (`model_qualification.offered_context_tiers`: a current `kriya model qualify --context-window N` record passing `context_capacity` + the model's role cases, or an operator-declared size while no qualification data exists; never above `max_context_tokens`/the trained length; exact Ollama runtimes only) and sends that `num_ctx` for that request only (attributed to the tier's own fingerprint); output grows above `max_tokens` only for a grounded `OutputExpectation` (the attempt measures existing targets for full-file rewrites), never above `max_output_tokens`. Refusals before inference: `ContextBudgetUnsatisfiableError` (`CONTEXT_BUDGET_UNSATISFIABLE`) or its subclass `OutputBudgetUnsatisfiableError` (`OUTPUT_BUDGET_UNSATISFIABLE`, Developer falls back once to an anchored patch). Expansions go to `LLMClient.budget_expansions` -> `GenerationState.drain_budget_expansions` -> `model.budget_expansion` run events in `traces.db`. `llm.context_policy` is SECURITY_AUTHORITY; the offered tiers are bound into the `model_runtime` resume fingerprint. `context_budget.estimate_tokens` (`len//4`) still drives context assembly - don't replace it wholesale.

### Fallback transitions, role metrics and model routing (`kriya/workflow/model_transition.py`, `kriya/core/role_metrics.py`, `kriya/core/model_routing.py`) — PRD-017..019
**Transitions (PRD-017):** every Developer call goes through `attempt._run_developer_generation`, which resolves the `ModelRequestProfile` of the model called (exact runtime, Developer qualification, capability profile, edit protocol, tools, JSON mode, served/allocation windows, the binding's OWN output budget - `FallbackModelConfig.max_tokens` unset is the shared `DEFAULT_OUTPUT_TOKENS` (read from the packaged `default_config.yaml` `llm.max_tokens`), never the primary's own override; one rule, `model_runtime.binding_output_tokens`). A change of profile is a `model.transition` run event (field-by-field `changes`); the retry no-progress fingerprint keys on the profile digest. A fallback that cannot serve the attempt - evidence only: a FAILED Developer qualification case, `runtime_profile: production` without QUALIFIED, a D1-mandatory patch (`_patch_required_files`) with a whole-file-only profile, no prompt room - is skipped for the next configured fallback that can serve (`_select_developer_fallback` at escalation, before the prompt is sized; `_substitute_for_required_patch` at the call for the attempt-specific patch reason), never sent a request, recorded as `model.fallback_selection`; run-wide skips live in `GenerationState.incompatible_fallbacks`, which `resolve_fallback_model(..., skip=)` (still the only escalation formula, order kept) and triage honour. Only when no remaining fallback can serve: the terminal `fallback_incompatible` failure (`FALLBACK_MODEL_INCOMPATIBLE`, `failure_category: fallback_model_incompatible`, every rejection in diagnostics). MISSING/STALE/non-exact are recorded, never refused. The Developer file-list request follows the model's JSON-mode capability.
**Role metrics (PRD-018):** all agents share one `LLMClient`; `role_metrics.model_role(role)` (a context variable) attributes calls - `BaseAgent.run`/`call_with_escalation(role=...)`, the Developer choke point and self-correction (`_as_developer`); unscoped = `unattributed`. `LLMClient._finish` counts every call per (role, model, exact runtime digest, inference settings digest) - routing's `metrics_row` only reads the candidate's own identity (a pre-identity row matches none); `GenerationState.record_developer_attempt_outcome` charges each deterministic gate outcome to the Developer runtime that generated it (only if it sent a request that attempt). Runs record `model.role_independence` (start) and one `model.role_metrics` (rows since the run's baseline); `kriya model metrics` aggregates `traces.db`. MODEL-EVIDENCE-HARDENING-001: every Planner response gets one typed outcome (`planner_repair.classify_planner_outcome`, a closed code table with a tripwire test: valid / malformed_output / structured_validation_failure / policy_rejected / other_failure; legacy `classify_plan_completeness` via `planner_outcome_for_completeness`; milestone plans with milestone validator codes; shadow planning under role `planner_shadow`, which routing never reads), charged to the answering model (`record_planner_outcome`, `RoleMetrics.record_structured_outcome`); malformed and structured validation failures also count as `schema_failures` (routing's failure rate), policy rejections do not. Work that ends outside `run_generation_workflow`'s own rows still reports its calls: the enforce controller writes `<run_id>.enforce` (status, `planning.failed`, `requirement.verdicts`, unreported metrics) at every enforce terminal, `kriya plan-milestones` writes `<group>.milestone-plan`, a direct run that raises writes `<trace_id>.exception` (`run_trace.record_run_exceptions` around `run_generation_workflow`; enforce: `.enforce` with status `error`; both re-raise), and the direct path's knowledge-gap/planner-rejection/baseline-indeterminate rows carry run events (`kriya/workflow/run_trace.py::write_outcome_trace`; never a RunRecord). `models.role_independence` (doctor) compares exact runtimes; its `required` flag follows `model_policy.independent_roles` (SECURITY_AUTHORITY), which `cli._workflow_config` also enforces before `generate`/`fix`/proposal execution build the engine (`ROLE_INDEPENDENCE_REQUIRED`). Metrics are observations: never verification evidence.

### Provider reply shape (E.1, MC3) — `kriya/core/inference_runtime.py`, `kriya/core/model_runtime.py`
The adapters check the TYPE of every provider field they read; a malformed reply is the existing retryable `malformed_provider_reply` REQUEST failure, never a raw structural exception (INTERNAL) and never a silent default. `tool_calls`: absent, `null` and `[]` are the only no-call shapes; any other non-list value (including the falsy `0`/`false`/`""`/`{}`) is malformed. A genuine coding error inside an adapter stays INTERNAL (`tests/test_provider_malformed_reply.py` pins both sides). **F3 (Wave-1 closure delta):** the `x or {}` idiom is gone from the decoders - a FALSY non-object where an object is defined (native `message` `0`/`false`/`""`/`[]`) is malformed (absent / `null` stay the empty-object shapes); a tool call is an object whose `function` object has a non-empty string `name` and `arguments` that are an object, a string or absent / `null` (native: `_native_tool_call`), and an OpenAI-compatible call needs string `function.name` (non-empty) and string `function.arguments` (`_raw_tool_call`) - nothing is fabricated into a `call_0` with an empty name.
