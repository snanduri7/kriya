### Embedding contract (`kriya/memory/embedding.py`, `kriya/memory/vector.py`) — EMBEDDING-CONTRACT-001
Measured (Ollama 0.34.4, nomic-embed-text): `/api/embed` with `truncate: false` refuses an over-context input (HTTP 400); `/v1/embeddings` and `/api/embed` without it silently truncate to the served context (2048).
- **No fake vectors (E1).** Every response is validated (count, one dimension, finite, non-zero norm); a failure is a typed `EmbeddingError` (`EMBEDDING_UNAVAILABLE` / `_MALFORMED_RESPONSE` / `_INPUT_TOO_LONG` / `_IDENTITY_CHANGED`), never a zero vector. Indexing publishes a file's vectors in one transaction (`LocalVectorStore.publish_file`); a file that cannot be fully embedded is `mark_stale` (old vectors stored but not current, its lexical text removed, cache entry cleared) and listed in `IndexReport.failed`; `kriya analyze` and `kriya learn` exit non-zero. A failed identity probe stops indexing.
- **No silent truncation (E2).** One endpoint, `/api/embed`, `truncate: false`; the provider's refusal is authoritative. `embed_chunks` batches, and segments a refused chunk deterministically at line boundaries (bounded depth), each segment keeping its parent chunk, segment index and the parent's source span; a local estimate (served context x 2 bytes) only pre-splits, and an estimate the provider refused counts as `admission_misses`.
- **Identity (E3).** `EmbeddingFingerprint` = model digest (/api/tags), adapter, dimension (a real probe), served context (/api/show), prefix policy, preprocessing and segmentation versions. Rows carry source digest, span, segment, generation, fingerprint and `is_current`; queries pass the fingerprint and see only current rows of exactly that identity. A different served identity (or a pre-contract index): `index_repository` drops the index and adopts the served identity in one transaction, then re-embeds every file through the normal path (`IndexReport.embedding_rebuilt_from`; no `--force` needed; two identities never coexist, an interrupted rebuild leaves a partial index of the served identity that the next `analyze` completes); until then a run degrades explicitly (`semantic_unavailable` = `EMBEDDING_IDENTITY_CHANGED`).
- **Transport and deadline (E4).** `configured_client(cfg)`: `trust_env=False`, `llm.transport` timeouts, at most one retry (transport error or 5xx only). Query-time calls take `run_deadline(cfg)` (the run's root clock); exhaustion stays `InferenceDeadlineError`.
- **Degradation.** `graph_retrieval.semantic_query_embedding`: a failed query embedding or another index identity sets `semantic_unavailable` (run event `retrieval.semantic_unavailable`); only the lexical leg (and graph) answers, with single-leg standing.
- **Doctor** `embedding.contract`: probe, digest, dimension, served context, `truncate:false` refusal probe, index fingerprint. **Tests** `tests/test_embedding_contract_001.py`; doubles in `tests/_fake_embedding.py`; `tests/conftest.py::_no_embedding_identity_probe` gives every test a fake identity (marker `real_embedding_identity` to test the real probe).

### Code Intelligence (`kriya/code_intel/`) — Code Intelligence R1
- **Structural model.** `parsing.py` is the only tree-sitter importer (Java + Python; pinned `tree-sitter>=0.25.2,<0.26`: 0.26.0 segfaults on CPython 3.14 when Node points are read); `config_parsing.py` adds configuration (Spring XML via expat, namespace-aware by LOCAL name - never strip xmlns; application/bootstrap properties and YAML, other `src/*/resources` properties except message bundles). Both return plain dataclasses (`model.py`: `Symbol` with a durable id = language + path + qualified key + overload parameter types, kind, spans with byte ranges, raw `source_digest`, modifiers/annotations/supertypes; `FileStructure` with `ParseState` PARSED / PARTIALLY_PARSED / UNSUPPORTED / PARSE_FAILED). Config kinds (`CONFIG_KINDS`: bean, bean_property, bean_constructor_arg, component_scan, config_import, config_key) are localization/read-only evidence, never mutation authority. Lines come from byte offsets, never `Node.start_point`. Facts are structural only, never type-resolved. Bump `STRUCTURAL_PARSER_VERSION` when extraction output changes (PyYAML's version is part of the parser identity).
- **Consumers.** `DependencyGraph._parse_java`/`_parse_xml`, `java_members.extract_java_members`, `context_source.java_member_boundaries` (behind `member_boundaries_for`) and the embedding chunker (`analyzer._structural_java_chunks` / `_structural_spring_xml_chunks`: one chunk per method/ctor of every type with its Javadoc; one per top-level bean) all read the models. There is no Java declaration regex left in those paths. Changing chunk text is an embedding identity change: bump `embedding.PREPROCESSING_VERSION` (the next `kriya analyze` rebuilds existing indexes).
- **BaselineIndex.** `store.StructuralStore` lives in `dependency_graph.db` (ci_files/ci_symbols/ci_fts), populated by `index_repository` from the same parse as the graph (code and configuration). Each file row carries its raw sha256 and parser digest; rows of another parser identity are never returned. The graph's `index_manifest` binds the structural identity, the embedding fingerprint and the repository revision; another identity drops all structure and re-parses, without re-embedding unchanged text.
- **Service.** `service.CodeIntelligenceService`: `refresh`, `current_view` (an in-memory overlay of files changed/added/deleted since indexing; never writes the index), `find_symbol`, `locate`, `search`, `get_member`, `member_at`, `build_context`, `with_overlay`. `get_member`/`member_at` always read the CURRENT bytes and re-parse when the index holds another digest: the index localizes, it is never mutation input.
- **Localization.** `locate.py` signals by regular extraction only (file:line incl. absolute paths of another root, Java stack frames, Python tracebacks, qualified/simple symbols, paths, string literals, FTS identifiers), fused by fixed tiers so exact evidence outranks similarity; the vector channel (`locate(semantic=...)`: the query's current-identity vector hits, crediting the members their indexed spans hold, rank-weighted, `VECTOR_MAX` in the similarity tier) is the only non-deterministic input; a named type scopes every member of its body (nested types included); every hit carries its channels.
- **Production retrieval.** `graph_retrieval.retrieve_graph_context` generates candidates with ONE fused query when a structural index of the current identity exists (`open_code_intelligence`); the legacy hybrid leg (`query_hybrid`) is a bounded fallback - whole without a structural index, else only for files without structure, in the similarity tier, reported as `legacy_only_files` (removal criterion in handover/CURRENT_STATE_MATRIX.md). Member hints = candidates' member ids verified against current bytes. Planner/Architect get a compact candidate map (ids, kinds, `candidate_signature`: a code member's annotation names + signature, a configuration entry's own declaration text from current digest-matched bytes, bounded at `CANDIDATE_SIGNATURE_CHARS`; channels; never bodies - SPRING-XML-PLANNER-EVIDENCE-001) inside the graph budget (`GraphRetrievalResult.rebuild_context` - request-fit rebuilds keep it); the enforce Planner gets the same map via `localization_candidates`. Events: `retrieval.code_intelligence`, `localization.decision`.
- **CI-6.** `kriya/workflow/localization_decision.py`: deterministic separation is "clear" (exact evidence and margin ≥ `CLEAR_MARGIN`, calibrated on loc-N) or ambiguous; only ambiguous localization makes ONE schema-constrained call (`LLMClient.complete_result(response_schema=)`, only on a runtime declaring `RuntimeCapabilities.json_schema_output` - today `ollama_native`; others are skipped typed, `STRUCTURED_OUTPUT_UNSUPPORTED`, never approximated; a schema is never dropped on retry). The whole response is one JSON object; every id must be a shown, current candidate; the decision only reorders (`adopt_decision`).
- **T0 across retries.** A package can render several member units for one file (every grounded member, every overload of an ambiguous name): `_record_known_target_package` keeps the highest-ranked as the path's record (`known_target_context_items`) and all of them in `GenerationState.known_target_member_items`; edit authority counts each unit whose bytes are in the request's mandatory text. `_prepare_retry_context` adds the run's own grounding (`_resolve_known_target_member_hints`, current bytes, no new authority) to every retry's failure-grounded members - a failure without a locator never evicts the causal member.
- **Developer T0.** Through `build_known_target_context` (the shared known-target seam): a grounded member's exact current body (`member_exact`, labelled with lines and raw revision) has its own budget (`exact_member_budget`: skills/optional context can never evict it); beside it the Code Intelligence package built from the same current bytes as an overlay (used imports, owner annotations/signature, fields, constructors, other member signatures, T1 collaborators, T2 linked tests, T3 linked config) - read-only tier `signatures`. `packing.build_package` renders the volatile member last. Event `developer.prompt_composition` records per-section tokens and the provider's measured prefill (`provider_metadata.prompt_eval_ms`). **Several targets (KNOWN-TARGET-MULTI-TARGET-STARVATION-001):** two passes - pass 1 gives every existing target its minimum authoritative unit (first grounded member, else the whole current source) against T0's room as well as the shared limit; pass 2 spends what is left on enrichment (further members, the package, signatures, a bounded excerpt). A minimum that fits nowhere is omitted `minimum_authority_unfit` and the invocation refuses typed (`CONTEXT_EDIT_PROTOCOL_UNSATISFIABLE`) before inference; one target can never starve another.
- **Index policy (E-01/E-13/E-17).** `analyze --changed` decides deletions from the full walk; deletions cover every index layer; a directory holding `skill.yaml`, the configured skills/memory roots and `.kriya/` are not indexed as source. Skill relevance uses `skills.mentions_term` (token-run equality, never substring). Vector queries read one cached float32 matrix per index generation (`LocalVectorStore.current_matrix`; every vector write bumps the generation in its transaction).
- **Benchmarks.** `benchmarks/code_intel/` (`coverage.py`, `loc_bench.py`, `pack_bench.py`, `vector_bench.py`, `ci6_bench.py`; repos under `~/kriya-bench`, pinned in its README with the measured tables). Tests: `tests/test_code_intel_*.py`, `tests/test_vector_matrix.py`; mutations in `evidence/code-intelligence-r1/`.
