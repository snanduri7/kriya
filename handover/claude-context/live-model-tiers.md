## Live-model CI tier (`tests/test_live_smoke.py`, `.github/workflows/ci.yml`'s `live-model-smoke` job)
Every other test in this repo runs against mocks - zero live LLM/embedding calls. `pyproject.toml`'s `addopts = '-m "not live_model and not live_static_analysis"'` excludes this tier (and PRD-031A's real-scanner tier) by default (both locally and in the `test`/`lint`/`lock-file` CI jobs); pass `-m live_model` explicitly to run it. CI runs a blocking supported-primary-model job and a scheduled three-model matrix. The bar is deliberately narrow: "did the real pipeline complete without crashing on a real API response shape," not code-generation quality. **Smoke contract (LIVE-SMOKE-CPU-TIMEOUT-001, `tests/_live_smoke_contract.py`):** a hosted `generate` smoke (`live_model and not live_target`, small CI model on CPU) passes on SUCCESS or an allowlisted typed model-capability failure (`SMOKE_CAPABILITY_FAILURES`), and only when every invariant holds: a real model request with its runtime recorded, a real Planner call (the roles reached are reported), retries within the ceiling, terminal settled RunRecords, the workspace untouched unless verified SUCCESS, no traceback/egress violation/commit without SUCCESS. Smoke configs set Kriya's own bounds tighter (`SMOKE_LLM_BOUNDS`, `SMOKE_AUTONOMY_BOUNDS`), never looser. Generation quality stays with PRD-035 (`live_target`), where a typed failure is FAILED. `skills.load_global` and `skills.load_cwd` control the implicit skill sources independently; set both false for a reproducible plain-Kriya run using only the explicit `paths.skills` directory.
