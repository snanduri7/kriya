## 2. Behaviour changes the owner should know (all stricter)
1. `kriya analyze` in a project without `paths.skills` no longer writes an auto-skill into Kriya's shared install skills directory after a warning: it refuses (MA7.4 rule) and completes the analysis.
2. Every atomic write now fsyncs (file + parent directory); a failing fsync/replace raises `DurableWriteError` (an `OSError`) where a plain `OSError`/silence occurred before.
3. Kriya now chmods to 0700/0600 the directories and files it owns under the state directory, authority home, `~/.kriya` (only when its state lives there; never created), and the workspace `.kriya` control/checkpoints at every run start; another owner's directory or a symlink stops the run (`PrivateStoreUnsafeError`). The candidate `.kriya/worktree` is not private (workspace content, container-mounted by design).
4. A planned `git diff` of a changed credential file is refused (`SENSITIVE_PATH_DENIED`) instead of printing it.
5. `deterministic_result` can now read `FAIL` (never `PASS` on a failed gate); the history projection says `succeeded: true` for a grounded expected non-zero exit.
