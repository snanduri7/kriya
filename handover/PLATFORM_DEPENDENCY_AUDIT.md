# Platform Dependency Audit (ARCH-PLATFORM-001)

Date: 2026-09-28. Base: `ea0627e` (every hosted CI job green, PRD-034 VERIFIED).
Scope: `kriya/**`, `plugins/**`, `scripts/**`, `tests/**`, `.github/workflows/ci.yml`, `pyproject.toml`, `requirements.txt`, the shell scripts, and the docs that describe platform behaviour.
Status: analysis only. No production code changed. Companion documents: `PLATFORM_ARCHITECTURE.md` and `PLATFORM_MIGRATION_PLAN.md`.

## 1. Method

1. **Import sweep.** Every import of `fcntl`, `resource`, `pwd`, `grp`, `termios`, `tty`, `pty`, `select`, `signal`, `msvcrt`, `winreg` and `shlex` in `kriya/`, `plugins/` and `scripts/`.
2. **Branch sweep.** Every `sys.platform`, `os.name`, `platform.system()` and `platform.machine()` branch.
3. **Implicit-dependency sweep.** Grouped by category:
   - identity: uid/gid;
   - permissions: chmod, `st_mode`;
   - processes: signals, `killpg`, `start_new_session`, `preexec_fn`;
   - hard-coded paths: `/bin/sh`, `bash`, `/tmp`, `/dev/*`, `/proc/*`, `/usr/*`;
   - executable lookup: `which`, `os.access(X_OK)`, `pathsep`;
   - home and temp locations: HOME, `~`, TMPDIR;
   - files: `os.replace`, rename, symlinks, `normcase`, `realpath` and every lexical containment idiom (`startswith(root + os.sep)`, `commonpath`, `"../"`);
   - quoting: `shlex`;
   - Git: configuration, EOL and file mode;
   - resource limits: RLIMIT;
   - locking: `flock`;
   - Docker: mount syntax.
4. **Reading the sites.** Each hit was read in context, not only counted.
5. **Behaviour probes on this host** (macOS 26 / APFS case-insensitive, Python 3.14). §4 holds the evidence. Every P0/P1 below rests on observed behaviour, not inference.

Severity:

| Level | Meaning |
|---|---|
| P0 | Platform behaviour can cause an unsafe commit, or bypass an authority or security guard. |
| P1 | A supported platform fails correctness or production execution. Also: a violation of an ARCH-PLATFORM-001 acceptance criterion that blocks PRD-036. |
| P2 | Portability debt that blocks a future supported platform (Windows), or a core leak that must move behind a port. |
| P3 | Convenience, tooling or docs. |

"Core leak?" means OS-specific mechanism or branching sits in a layer that should hold only policy or orchestration (`workflow`, `policy`, `control`, `config`, `core` orchestration), rather than in a tool or adapter module.

## 5. The explicit assessments the directive requires

| Topic | Finding | Assessment |
|---|---|---|
| `fcntl.flock` | PLAT-003, PLAT-004 | This is the only hard import blocker for Windows. The semantics are right for POSIX: the lock is released on process death and is advisory. A Windows provider using `LockFileEx` on a handle also releases on process exit, so the same contract (`FILE_LOCK_CRASH_SAFE`) is implementable. No workflow change is needed, because callers already go through `run_coordinator` and `acquire_run_lock`. |
| `RLIMIT_*` | PLAT-005/006/007 | CPU: enforced on macOS and Linux. AS: enforced on Linux, advisory on macOS (the evidence overclaims), bypassed for JVMs (by design). Windows: none today, and silent. The replacement is a Job Object (CPU time plus job memory: a committed-memory limit, which is a **stronger** memory primitive than RLIMIT_AS). The strategy decision must stay Kriya policy. |
| Process groups / signals | PLAT-008, PLAT-009 | POSIX session plus `killpg(SIGKILL)` at four spawn sites. The Windows equivalent is a Job Object with `KILL_ON_JOB_CLOSE`. `signal.signal` and `add_signal_handler` are not used anywhere (good). |
| uid/gid / container identity | PLAT-012, PLAT-013, PLAT-014 | The Linux fix is correct and sits below the containment port, but it reads `os.getuid` directly and is duplicated in the MCP adapter. Docker Desktop on macOS maps ownership through its file-sharing layer, native Linux maps uids 1:1, and Windows (WSL2) presents 9p/drvfs ownership. These are **runtime** differences and belong in `ContainmentBackend` capabilities, not host-OS branches. |
| Path semantics | PLAT-001, 002, 017-021 | **The largest real exposure.** Around 17 hand-written, lexical, case-sensitive containment or identity checks. On macOS (APFS case-insensitive, normalization-insensitive) the outside-required checks and the exact-string protected-path check **fail open**. Windows adds `\`, drive letters, UNC, reserved names and alternate data streams. |
| Shell / script dependencies | PLAT-010, PLAT-011, PLAT-014, §3 | Host shell: ShellTool only. Container shells are fine. Policy recognizers assume POSIX shell grammar. Certification is Bash. |
| Filesystem atomicity / permissions | PLAT-022/023/024 | POSIX atomic replace plus directory fsync are correct. On Windows: replace over an open file fails (already typed, so safe), there is no directory fsync (silently skipped), and mode bits are synthetic. |
| Temp / home / state paths | PLAT-028, PLAT-031 | `~/.kriya` works everywhere but is resolved in nine places. Temp files use `tempfile` (portable); one literal `/tmp` normalization. |
| Docker host differences | PLAT-012/013/014 | Mount syntax (colon), the ownership model, and the Linux-containers requirement. All are expressible as containment-runtime capabilities. |
| Executable discovery / quoting | PLAT-011, PLAT-032, PLAT-033 | `shutil.which` is portable. Basename vocabularies ignore `.exe`/`.cmd`. `shlex` and `shlex.join` are POSIX-only quoting (`dependency_execution.py:392` is in-container, so fine). |
| Git line endings / file mode | PLAT-025, PLAT-026, PLAT-027 | Kriya pins `core.hooksPath` but no EOL, mode, symlink or case settings, so worktree fidelity depends on the user's git configuration. |
| Platform-only dependencies / imports | PLAT-003, PLAT-036 | `fcntl` is the only unconditional one. `resource` is already lazy. No POSIX-only third-party package. |
