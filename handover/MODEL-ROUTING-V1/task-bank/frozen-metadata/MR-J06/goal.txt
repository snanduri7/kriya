When a JdbiPlugin wraps or replaces the JDBC Connection in its `customizeConnection` callback (for example to return a proxy that intercepts `close()`), Jdbi no longer closes the customized connection when the Handle is closed: it closes the underlying connection instead, so the wrapper's `close()` is never called. This behavior changed somewhere between 3.37.1 and 3.45.0. Make the Handle opened by `Jdbi.open()` (and the convenience methods built on it) release the connection returned by the plugin chain, i.e. the customized one. If a plugin's `customizeConnection` throws, the connection must still be closed and the exception propagated, as before.
