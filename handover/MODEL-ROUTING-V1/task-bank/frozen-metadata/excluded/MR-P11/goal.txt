Parsing TOML text with very deep nesting crashes tomlkit with a RecursionError instead of reporting a parse error. Examples that currently crash: `x = ` followed by 500 `[`, then `1`, then 500 `]`; the same with 500 nested inline tables (`x = {a = {a = ... 1}}`); 500 nested arrays of inline tables (`x = [{a = [{a = ... 1}]}]`); a bare dotted key with 500 parts (`a.a.a. ... .a = 1`); and table headers with 500 dotted parts (`[a.a. ... .a]` and `[[a.a. ... .a]]`, each followed by `x = 1`). Make `tomlkit.parse` raise `tomlkit.exceptions.ParseError` for a document whose value nesting depth or dotted-key length exceeds a limit, instead of recursing until the interpreter gives up. Expose the limit as an integer class attribute `MAX_NESTING_DEPTH` on `tomlkit.parser.Parser`, default 100, so a subclass can change it. A document nested exactly `MAX_NESTING_DEPTH` levels deep (that many `[` around a value, or a dotted key with that many parts) must still parse and round-trip unchanged through `as_string()`. Documents within the limit keep parsing exactly as before.
