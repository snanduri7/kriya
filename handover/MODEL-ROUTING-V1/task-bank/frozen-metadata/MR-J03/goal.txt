When Gson deserializes a Map whose keys are read from JSON object member names (for example a Map<String, String> read through a TypeToken), a parse error that happens after a key has been consumed reports an incorrect JSON path. For example, parsing the malformed input {"name":"value into a Map<String, String> produces an "Unterminated string" error whose path is `$.` (the member name is missing), whereas reading the same input directly with JsonReader (beginObject, nextName, nextString) correctly reports `$.name`. Make the JSON path reported in such errors include the key that was just read, so it matches what JsonReader reports. This must hold both when the JSON is parsed from text/streams and when it is deserialized from an already parsed JsonElement tree, and it should also apply to the error message for duplicate map keys. In particular, a map key that Gson reads by promoting a member name to a value (JsonReaderInternalAccess.promoteNameToValue, used for object-encoded map keys) must update `getPath()` and `getPreviousPath()` of the reader as soon as that key has been consumed, for both the stream-based and the tree-based reader. Successful parsing must not change.
