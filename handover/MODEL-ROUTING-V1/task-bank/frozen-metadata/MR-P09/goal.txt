When a field uses `validation_alias=AliasChoices(AliasPath("custom_config", ...), "my_field")` together with a custom settings source set up alongside the environment/dotenv sources, a value that is present under the plain alias (here `MY_FIELD` in a `.env` file) is reported by the env source under the first AliasPath element (`custom_config`), so it ends up interfering with the other source and the field validates to its default value instead of the value from the `.env` file; reversing the order of the choices gives the right result. The order of the choices must not matter: the value found through a matching alias must be returned under the key of the alias that actually matched.
