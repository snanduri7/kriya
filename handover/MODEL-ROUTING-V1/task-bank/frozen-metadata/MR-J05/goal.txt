Constructor resolution picks the wrong overload when the arguments include null and the candidates are varargs constructors. Given a class with the constructors `Test(Test test, int... values)` and `Test(int... values)`, where the second constructor contains the explicit constructor invocation `this(null, values);`, resolving that invocation with the symbol solver (JavaSymbolSolver with a ReflectionTypeSolver) should resolve to the constructor whose signature is `Test(Test, int...)`. The same class with `this(new Test(), values);` already resolves correctly. Fix constructor overload resolution so such calls resolve to the most specific applicable constructor, consistently with how method overloads are resolved.
