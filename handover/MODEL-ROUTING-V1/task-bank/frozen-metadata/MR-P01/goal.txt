attrs checks that mandatory attributes do not follow attributes with defaults before it runs a user-supplied `field_transformer`. That makes it impossible to use a transformer to fix such an ordering problem: for example a transformer that sorts fields by a `metadata` key so that the defaulted field `x` ends up after the mandatory field `y` is never reached, because the class definition already raises "No mandatory attributes allowed after an attribute with a default value". A class must be accepted when the field list produced by its `field_transformer` is valid, even if the fields as declared are not (transformers may reorder fields, give them defaults/factories, make them keyword-only, or remove them), while classes whose final field list is invalid must still be rejected with the existing error.
