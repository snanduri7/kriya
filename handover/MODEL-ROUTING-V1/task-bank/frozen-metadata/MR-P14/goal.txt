`jsonschema.exceptions.best_match` can choose an error from a branch of the schema that does not apply to the instance's type. With the schema `{"properties": {"foo": {"anyOf": [{"type": "array", "minItems": 2}, {"type": "string", "minLength": 10}]}}}` and the instance `{"foo": "bar"}`, the instance is a string, so the useful error is the `minLength` failure from the string branch, but `best_match` reports a different one (the array branch's error). The result must not depend on the order of the branches: listing the string branch first must also give the `minLength` error. Make the default relevance ordering used by `best_match` prefer errors whose sub-schema declares a `type` that the instance matches over errors whose declared type does not match. Errors from schemas without a `type` keyword, and boolean schemas such as `{"properties": {"foo": False}}`, must keep working exactly as before, and the existing relevance rules (shallower path first, weak and strong validators) keep their precedence.
