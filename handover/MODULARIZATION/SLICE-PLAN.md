# SLICE-PLAN

Binding context: branch `arch/full-modularization-v1` from `kriya-pre-full-modularization-20261016` (= `a91157f`); Phase 0 is done. Every slice commits LOCALLY only (owner decision 1); nothing is pushed or merged before the single final independent review (Q2) and its one focused re-review. No `Co-Authored-By`. One slice = one Opus agent working only from these six documents + the code.

Fixed per-slice method (owner decision 12): characterize -> add architecture/behaviour tests first -> identify ownership -> extract with behaviour preserved -> focused tests -> (only in a correction slice) the authorized generic correction -> negative/mutation tests -> adjacent integration -> `.venv/bin/pylint kriya plugins/core_tools tests` and `.venv/bin/ruff check .` both exit 0 -> commit locally -> append one status line to §9 of this file (slice id, HEAD, tests run, tests NOT run) and regenerate `tests/architecture/baseline.json` when the slice changed an edge. Never combine a physical move, a rename, a semantic correction or unrelated cleanup in one commit. A slice that discovers a product defect outside its scope records it in `handover/BACKLOG_REGISTRY.csv` with `target_scope` = the slice that owns it (ENGINEERING_RULES §9 applies if it is in scope).

Size classes (one Opus context): **S** <= 3 production files and <= ~400 changed lines; **M** <= 6 production files and <= ~1,200 lines; **L** exactly one god-module seam, <= ~2,000 lines moved, no other production file beyond the new owner module and the facade. Anything bigger is split here already.

Field legend per slice: `goal` / `files` (new + changed) / `patch points & guards` (what must keep working or be rewritten in-slice) / `kind` (PRESERVE = behaviour-preserving, CORRECT = authorized behaviour change) / `stop-list` (plan §13 item; "owner-authorized" when covered by decisions 2-5) / `gate` (what runs first) / `tests` (added) / `mutants` / `commands` (Tier 1; Tier 2 per TEST-MATRIX §4) / `commit` / `deps` / `size`.

## 0. Owner directive 2 (2026-10-16) - BINDING; where a slice text below conflicts, this section wins

**Execution units.** The 64 slices are ACCEPTANCE units, each keeping its own coherent LOCAL commit, tests and status line; they are not 64 agent contexts. **Order for every Scenario-04 semantic area (A-E):** characterization -> ownership extraction -> preservation proof -> semantic correction -> correction tests + mutants -> integration. **Budget (H2/H4).** Approved with one requirement: the 1800 s allowance is an explicit, documented default constant `HUMAN_WAIT_ALLOWANCE_SECONDS` owned by `workflow/budget_policy.py` and exposed as `autonomy.budgets.human_wait_allowance_seconds`; no other module contains that literal (a `test_kernel_purity`-style grep test enforces it). Required tests (H4): the recorded human wait still admits the fallback pass when active budget remains; active model work still exhausts the generation budget; human wait advances total wall clock; `run_liveness_seconds` terminates a genuinely hung/abandoned run (fake clock); liveness termination and generation-budget exhaustion are DIFFERENT typed reason codes with their own evidence. No new timeout abstraction unless evidence requires it.

**Attribution / retry target (F1-F5).**
- F1 first classifies EVERY current producer of `failure.authoritative_files` by PROVENANCE (MODULE-CONTRACTS `Provenance`), measured from the producing code, and finds every recorded failure carrying both an exact locator and a file set; the conflict rule is derived from provenance and pinned by a regression test from the real case. No rule from field names.
- F2 types `AttributionSource{provenance, authority_level, evidence_ref}` and `RetryTargetDecision` (unresolved findings, authoritative locator, advisory evidence, rule applied, selected, rejected candidates + why, origin original/expansion/fallback) as ONE recorded decision (`retry_target.decision`).
- F4 correction = expansion rule (MODULE-CONTRACTS §12): a model filename mention never replaces or overrides an unresolved deterministic locator; advisory file B may expand the target only after locator file A was staged, re-gated, and the same normalized failure signature remains, with B inside the legal write scope and no stronger deterministic contradiction; structural dependency evidence used when it exists. Six mandatory controls with tests+mutants: (1) bare mention cannot redirect; (2) a quoted compiler message naming another file cannot redirect; (3) the deterministic locator stays authoritative; (4) after A genuinely fails with the same signature, advisory B may be considered (the PRV-05 case); (5) B outside the allowed scope is refused; (6) a successful deterministic repair of A prevents any advisory redirect. This supersedes the weaker "locator exhaustion" wording of §4 decision 1.
