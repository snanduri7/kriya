# TARGET-MODULE-MAP

Decision rule (owner decision 9): a module is modular when its ownership and public contract are explicit, callers depend on the contract, internals are not imported across the boundary, the dependency test enforces it, hidden patch/import coupling is gone and a targeted suite exists. Physical location is chosen per module by the patch-target cost measured in CURRENT-DEPENDENCY-MAP §8: **A** = extract the contract in place (file stays, a public contract module is declared), **B** = physical move with every patch target / guard path updated in the same slice, **C** = physical move behind a temporary facade (re-export only; never a second implementation) with a named removal slice. A facade never redirects `mock.patch`; so C is used only where the moved module has <= 3 patch-target files and those files are updated in the same slice, and the facade exists for the plain `import` sites.

Logical modules are declared in ONE table, `tests/architecture/module_map.py` (slice A1): `{logical module -> (python packages/modules it owns, its public contract modules)}`. The architecture test keys on this table, not on folder names, so A-type decisions are enforceable exactly like B-type ones.

## 3. God-module decomposition (KERNEL, owner decision 6)

Pattern for every seam (the PRD-030 pattern, TRACED in `terminal_gate_service.TerminalGateValidators`): the facade module keeps the patched names as module-level functions; the extracted owner module takes what it needs as parameters or as a small frozen `*Deps` dataclass built from the facade's names at the call site. The owner module never imports the facade (architecture test: `workflow.attempt`, `workflow.workflow`, `workflow.workflow_controller`, `cli` are importable by nothing except tests, the client/application layer and each other in the documented direction).
