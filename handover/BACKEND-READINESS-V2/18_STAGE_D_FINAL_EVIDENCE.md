## 9. D9 - legacy `_LITERAL` forensics (MEASURED)
`example_oracle_java._LITERAL` is a raw string with doubled backslashes: it accepts a string escape only when written with TWO backslashes (`"a\\tb"`), and rejects EVERY single-backslash escape: `"a\tb"`, `"a\"b"`, `'\n'`, `'\u0041'` (a real TAB character and raw non-ASCII are accepted). Java semantics: `\t` is one TAB; `\\t` is backslash+t, so the legacy pattern accepts the wrong spelling and rejects the right one. Across the 23 static-call arrow lines of all 31 distinct recorded goals the corrected pattern would newly accept 0 lines, so correcting it would not change any recorded compiled-example behaviour. Disposition: NOT patched in the legacy enforced forms (no recorded effect, not required by the slot-A work); the corrected pattern is used by `goal_example_forms` (the instance form graduated on it; T3's `"my\tfoo"` is compiled there). Patch it together with any future module-aware T3 work, or standalone with the full parser test matrix.
