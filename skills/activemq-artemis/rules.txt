Use org.apache.activemq:artemis-server and org.apache.activemq:artemis-amqp-protocol Maven dependencies for an embedded ActiveMQ Artemis AMQP broker (version 2.31.2).
Do not use artemis-core-server; use artemis-server instead.
ActiveMQ Server configuration requires setting persistenceEnabled, journalDirectory, bindingsDirectory, pagingDirectory, and largeMessagesDirectory.
AMQP protocol support requires adding AMQPProtocolManagerFactory to ProtocolManagerFactories list in ConfigurationImpl.
AMQP acceptor port defaults to 5672 (using tcp://localhost:5672?protocols=AMQP).
Use javax.jms:javax.jms-api:2.0.1 for JMS API dependencies.
If any JVM flags (e.g. Java 17's --add-opens) are needed, use the exec:exec goal, NOT exec:java - exec-maven-plugin 3.1.0's "java" goal (exec:java) has no "jvmArguments" parameter at all (confirmed by reading the actual mojo descriptor from the jar) and runs inside Maven's own already-started JVM, so it cannot apply JVM startup flags even in principle. Use <executable>java</executable> with every flag as its own <argument>, then <argument>-classpath</argument> and the bare <classpath/> element, then the main class as the final argument. Run via `mvn -q compile exec:exec -Dexec.mainClass=...`, not exec:java. See examples/pom.xml for a complete, verified-working reference.

The final <argument> in exec:exec's <arguments> list (the main class to run) must be ${exec.mainClass}, not a hardcoded literal class name - confirmed live: a literal value ignores `-Dexec.mainClass=...` on the command line and always runs that class regardless. Set a sensible default via an <exec.mainClass> property, so `mvn exec:exec` with no override still works, while every class in a multi-entrypoint project stays independently runnable via its own -Dexec.mainClass override.
